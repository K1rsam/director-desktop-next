# M6.3 · Canvas 只读进程阶段证据

基于 M6.2 `5c5d9cc9816e0287233cf5411144d015e75f31a4` 的诊断补丁。原生 GUI 的 version 阶段发生 `CLI_TIMEOUT`，相同 CLI 在独立调用中可快速完成；本补丁不声称已经确定或修复 Mac 原因。

## 保持执行规则

单命令 10 秒、整轮 45 秒及既有排空/清理期限不变。deadline-first select 顺序、一次清理前 `try_wait`、终止和回收路径不变；不增加重试或登录，不修改 SSL、代理、环境、凭据、生成或签名。仅 Canvas 显式检查开启观察器，其余调用不采集这些诊断。没有新增 IPC 或安全策略旁路。

已知旧诊断歧义：运行期限与排空期限可以同一时刻到达，优先分支可能返回 `CLI_TIMEOUT`，即使此前已观察退出；在期限边界已就绪的退出/EOF 也可能晚于超时分支处理。因此错误码本身不能证明子进程当时仍运行。M6.2 后处理解析器位于监督器成功返回之后，不能直接解释版本阶段此错误。

## 安全观察内容

`details.processDiagnostics[固定命令].supervisor` 在成功和失败路径均保留：

- 本次自有子进程历史 PID
- 相对单次命令开始的单调毫秒时间：线程、runtime、spawn、退出观察、超时、清理、runtime drop、线程 join
- stdout/stderr 已观察字节数、首字节时间、EOF 及读取错误标志；不包含实际输出
- 监督器实际观察到的退出码/信号、控制循环次数/最大间隔、期限超出量
- 既有清理前 `try_wait` 的实际结果：运行、已退出、查询失败；终止请求和最终回收确认

未观察到的事实保持 null/未知。`preCleanup=running` 只描述该次查询时刻；历史 PID、最后阶段、退出和回收结果不表示当前进程状态。主错误保持原值；清理后的退出不被转换为成功，也不会自动重发。

界面提供折叠的“Canvas 进程阶段诊断”。命令、阶段、字段和枚举使用固定白名单，数字/布尔严格校验；未识别值不原样展示。没有原始输出、参数、路径、环境、账户、token 或用户材料进入观察器；进程证据仅附于本次只读结果。

## 回归与后续核验

合成可执行文件覆盖：正常静默短进程、子进程已退出但后代持有输出管道、仍在运行的子进程超时、监督线程延迟后发现子进程已退出。最后一种仍返回超时、不请求终止已经退出的 PID、不把迟到退出当按期成功。完整 `readiness.check` 的 version 超时用例验证错误路径仍向 GUI 交付观察证据，且不继续 schema/账户检查。

原生下一次检查应读取本补丁提供的阶段事实，再针对已证实的分支修复；不得凭独立终端成功推断 GUI 子进程环境等同，也不得用超时后无残留进程推断其自然退出。
