# 有界原生 CLI 验收入口（M2）

普通macOS/Windows桌面启动使用标准版入口，开放已实现渠道及文字流程，保留独立的域验证、费用和恢复约束。本机应用数据目录存在有效 `native-cli-acceptance.json` 时，普通双击启动优先恢复同一有界文字测试授权，无须重复传启动参数；原文、模型与既有工作流预算约束不变。无效授权报错，不静默扩大范围；隔离启动探针始终忽略该文件并保持离线。此入口不能替代真实平台、账号、模型可用性和创作质量验收；当前未接入的Stage3、生产SDK及Canvas生成桥仍受各自门禁约束。

## 启动与范围

持续运行的 macOS/Windows 桌面程序支持 `--native-cli-acceptance <绝对授权文件路径>`。授权文件由本地测试协调者根据已批准文件和本应用锁源结果生成并保留在独立私有测试目录，不提交仓库。Linux 启动此模式直接失败。不能与 `--verify-startup` 合用。

授权 JSON 使用 `native-cli-acceptance/v1`，精确包含：

- `version`、独立 `grantId`
- 已批准 DOCX 字节的 `approvedDocumentSha256`
- 本程序解析后精确文本的 `lockedSourceSha256`
- `episodeCount: 10`、`storyboardEpisodeNumbers: [1, 2]`
- `backend: "codex"`、`model: "gpt-6.1-sol"`、`reasoning: "medium"`

拒绝未知字段、错误源哈希、重复/缺失集号、未处理锁源诊断、改变模型/推理强度、自动降级，以及改变同一授权内容来重置预算。工程代理的 Max 配置与应用的 medium 配置是两个不同参数。

原生模式只允许一份源的 Stage1 完整十集文字分析、Stage2 资产提示词设计，以及完成适配后精确 EP1/EP2 的 Stage3 文本流程。当前 `creative_runtime_ready()` 固定为 false，Stage3 新派发仍被阻止；规则来源匹配不意味着适配已经完成。官方 SDK 的共享 Rust 路径已接通并有真实 SDK 包离线测试，但生产 SDK 调用仍关闭，不回退 CLI。图片、视频、自动批量、其他集、换项目/换授权重置范围均被拒绝。少量免费图片案例仍需单独核验并实现对应门禁，本入口不开放图片。

## 持久预约与崩溃恢复

每份锁源的每个阶段最多绑定一个原工作流。预约先写入独立 app-home 的 `native-acceptance.sqlite`，创建工作流时冻结程序生成的预约回执，然后绑定原 ID 与完整快照摘要，绑定完成前不启动执行线程。配置变化不改写原请求。

进程还持有 `native-acceptance-owner.sqlite` 的 SQLite 排他写事务作为存续锁。另一个原生进程不能抢占；操作系统在崩溃/退出时释放该锁，不使用 PID 猜测或删除过期锁文件。

重新启动后，在启动任何工作线程前核对未绑定预约：

1. 唯一持久父工作流且精确回执/冻结设置匹配：绑定原 ID，保留原任务，等待明确续跑
2. 无父工作流、无同阶段文本执行证据：以同一事务写入“确认未派发”的审计并标记可重试；重新保留预约时再次审计，不形成已执行预算豁免
3. 多个匹配流程、回执/设置不符、孤立文本或其他不明证据：保持预约，不新建任务；不能靠换项目或换授权解锁

`images.design` 续跑继续原父 workflow，复用原冻结美术设置、方向、比较上下文和规则版本；核对源、目标资产与直接来源链语义、相关视觉事实。子文字步骤的 checkpoint 分别绑定资产/变体、事实包及有限修复身份，未知 SDK/CLI 提交仍然占位。部分失败时保留原回包和已通过子步骤，但不采用部分资产或推进制作基础版本；全量通过时，资产/事实采用与原父工作流完成在同一个 SQLite 事务提交，避免采用后崩溃又续跑。完成的流程不能重复续跑。原生预约、未知提交和既有修复预算不因新界面选择而重置。

## Headless 进程边界

`director-next-core` 是单请求读写工具，不是常驻制作服务。它在解析原生异步生成/续跑请求后、创建 Engine 或任何 app-home/预约/任务前返回 `HEADLESS_ASYNC_ACCEPTANCE_BLOCKED`。这些验收操作必须通过持续运行的桌面程序派发，避免“后台线程刚启动，主进程就退出”。只读/诊断操作仍受平台和授权检查。

## 本轮证据与未验证项

所有云端用例使用合成数据；未调用真实 CLI/SDK 模型、账号、图片或视频。离线测试覆盖阶段范围、源和模型锁定、重启预算、跨项目/授权拒绝、存续锁、预约崩溃间隙、审计失败回滚、Stage2 同工作流恢复和 headless 子进程拒绝。

macOS/Windows 上的持久凭据、退出和进程树、真实 CLI 版本/模型、打包分发和旧采用 EP1/EP2 质量比较尚未通过 M2 验收。具体结果只以 `verification/M2.json` 及其日志为准；不得用 Linux 通过替代原生通过。
